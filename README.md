# LeakedPassChecker

LeakedPassChecker — настольное приложение для анализа возможного использования учетных данных сотрудника без его фактического присутствия на объекте. Приложение сопоставляет данные из журнала проходной и журнала входов в систему, формирует сводку по результатам проверки и позволяет выгрузить отчет в Excel.

## Назначение

Проект предназначен для оперативной проверки инцидентов, связанных с потенциальной компрометацией паролей или некорректным использованием учетных записей. Основной сценарий работы — выявление записей входа в систему, для которых отсутствует соответствующая запись о проходе сотрудника.

По итогам проверки записи распределяются по категориям:

- `Утечки` — есть вход в систему, но нет записи о проходе.
- `Исключения` — записи, исключенные из анализа по списку исключений или списку уволенных.
- `Нет входа` — есть запись о проходе, но нет входа в систему.
- `Сопоставлено` — найдены и запись о проходе, и вход в систему.

## Функциональные возможности

- Загрузка журнала проходной из Excel-файла.
- Загрузка журнала входов в систему из Excel-файла.
- Поддержка списка исключений в формате TXT.
- Поддержка списка уволенных сотрудников в формате TXT.
- Проверка структуры входных таблиц перед анализом.
- Нормализация ФИО для сопоставления записей.
- Отображение статистики по результатам проверки.
- Экспорт результата в Excel с отдельными листами по категориям.

## Установка

Клонируйте репозиторий и перейдите в каталог проекта:

```powershell
git clone <repository-url>
cd LeakedPassChecker
```

Создайте и активируйте виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
pip install -r requirements.txt
```

## Запуск

Запустите приложение командой:

```powershell
python main.py
```

После запуска откроется графический интерфейс, в котором необходимо выбрать входные файлы и нажать кнопку `Начать поиск`.

## Входные данные

### Журнал проходной

Файл должен быть в формате `.xlsx` или `.xls`. Приложение ожидает заголовки в строке 7, в столбцах 1-6:

```text
дата | отдел | фио | таб. № | события | события
```

Данные анализируются начиная со строки 9.

### Журнал входов в систему

Файл должен быть в формате `.xlsx` или `.xls`. Приложение ожидает заголовки в строке 11, в столбцах 1-8:

```text
user name | client host name | logon time | event type text | failure reason | message | user display name | user distinguish name
```

Данные анализируются начиная со строки 12.

### Список исключений

Необязательный TXT-файл в кодировке UTF-8. Каждая строка содержит отдельное значение или шаблон исключения. Поддерживаются маски:

- `*` — любое количество символов.
- `?` — один любой символ.

Исключение может применяться к ФИО, отделу, табельному номеру, имени пользователя, имени рабочей станции и другим полям входа.

### Список уволенных

Необязательный TXT-файл в кодировке UTF-8. Каждая строка содержит ФИО сотрудника. Сотрудники из этого списка относятся к категории `Исключения`.

## Экспорт результата

После завершения проверки нажмите кнопку сохранения результата и выберите путь для Excel-файла. В отчет включаются листы только по тем категориям, в которых есть данные:

- `Утечки`
- `Исключения`
- `Нет входа`
- `Сопоставлено`

Для каждой записи выводятся данные сотрудника и связанные события входа в систему. Строки с событиями группируются внутри Excel-отчета.

## Ограничения и особенности

- Сопоставление выполняется по нормализованному ФИО.
- Для корректной проверки входные таблицы должны соответствовать ожидаемой структуре заголовков.
- Если необязательный файл исключений или список уволенных не выбран, соответствующая проверка пропускается.
- При ошибках чтения файлов или несоответствии структуры таблиц приложение выводит предупреждение в интерфейсе.
